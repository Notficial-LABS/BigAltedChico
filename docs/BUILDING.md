# Building BigAltedChico

Use CMake 3.24+, Python 3, a C++17 compiler and JUCE. The current tested baseline is **JUCE 9.0.4**. Download JUCE from its official distribution or source repository and pass its source directory as `JUCE_DIR`; it is intentionally not vendored into this repository. Read [licensing](LICENSING.md) before distributing the combined binary.

Signalsmith headers, Roboto and skin artwork are already included. CMake generates the embedded skin archive from `SkinTemplate/` into the build directory. Python is a build-time tool, not a plugin runtime dependency.

## macOS

Validated locally on Apple Silicon with Apple Clang 21, CMake 4.2.3 and macOS deployment target 12.0. Install Apple's Command Line Tools and CMake, then:

```sh
cmake -S . -B Working/build \
  -DJUCE_DIR=/path/to/JUCE \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=12.0
cmake --build Working/build --config Release --parallel 6
```

Built targets: `BigAltedChico_Standalone`, `BigAltedChico_VST3`, `BigAltedChico_AU`. Products are in `Working/build/BigAltedChico_artefacts/Release/`.

The helper `./build.sh build` builds without installing. Set the `JUCE_DIR` environment variable to your JUCE source directory. If unset, the helper also recognises `$HOME/Applications/JUCE-9.0.4`. `./build.sh install` explicitly copies VST3 to the user plugin directory and moves the previous installed bundle into `Working/Backups/`. AU can be copied manually into `~/Library/Audio/Plug-Ins/Components/`.

`./build.sh preview` builds and opens the Standalone. `python3 watch_preview.py` rebuilds it after C++ source changes; this convenience watcher is macOS-only. Builds are ad-hoc signed for local development, not Developer ID signed/notarized releases.

To generate the local macOS arm64 test installer after building all three formats:

```sh
python3 Tools/package_macos.py
```

Output: `Working/Instalers/MacOS/BigAltedChico-0.1.0-macOS-arm64-preview.pkg`. Open it in Finder, then select AU, VST3 and/or Standalone in Installation Type. Destination Select offers all users (`/Applications` and `/Library/Audio/Plug-Ins`) or only the current user (`~/Applications` and `~/Library/Audio/Plug-Ins`). The all-users option requires administrator authorization. Close the Standalone and DAWs before installing. This local package is unsigned and not notarized. The maintainer has manually tried the installer; broader upgrade/uninstall and compatibility checks remain ongoing. No Windows/Linux installer is generated by this script.

Intel or universal builds require their own compilation and testing. This repository does not claim those architectures have passed validation.

## Windows — native build instructions, runtime validation pending

Install Visual Studio 2022 with Desktop Development with C++, CMake, Python 3 and JUCE. In a developer terminal, use an x64 build directory:

```powershell
cmake -S . -B Working/build-windows -G "Visual Studio 17 2022" -A x64 -DJUCE_DIR="C:/SDKs/JUCE"
cmake --build Working/build-windows --config Release --target BigAltedChico_VST3 BigAltedChico_Standalone --parallel
```

AU, VST2 and AAX are not targets on Windows. A local cross-compiled x64 preview exists; native Visual Studio compilation and actual Windows execution remain to be validated. Package a native build with `python Tools/package_windows.py --build-dir Working/build-windows`.

## Linux — build instructions, not yet validated

Install a C++17 compiler, CMake, Python 3 and JUCE's Linux audio/windowing development dependencies. For Debian/Ubuntu, the core dependencies normally include `build-essential`, `pkg-config`, `libasound2-dev`, `libx11-dev`, `libxext-dev`, `libxinerama-dev`, `libxrandr-dev`, `libxcursor-dev`, `libfreetype6-dev`, `libfontconfig1-dev` and `libgl1-mesa-dev`. Resolve package names for the chosen distribution and JUCE version. Web browser and curl support are disabled in this project.

```sh
cmake -S . -B Working/build-linux -DJUCE_DIR=/path/to/JUCE -DCMAKE_BUILD_TYPE=Release
cmake --build Working/build-linux --target BigAltedChico_VST3 BigAltedChico_Standalone --parallel
```

AU, VST2 and AAX are not targets on Linux. UI checks need a graphical display; a CI environment would need an appropriate virtual display. Linux binaries/installers remain unvalidated.

## Checks

Run from the repository root so the checks can find `SkinTemplate/`:

```sh
./build.sh check
```

Or enable `-DBIGCHICO_BUILD_CHECKS=ON`, build `BigAltedChicoChecks` and `BigAltedChicoHostChecks`, then run the executables. The full checks write WAVs/CSV to `Working/Tests/` and UI snapshots to `Working/Previews/`. The host checker takes an absolute VST3 bundle path. For UI-only checks, pass an absolute snapshot path followed by `--preview-only`.

Optional render analysis:

```sh
python3 -m venv Working/venv-analysis
Working/venv-analysis/bin/pip install numpy scipy soundfile
Working/venv-analysis/bin/python Tools/analyse_audio.py
```

## Skin Kit

```sh
python3 Tools/package_skin_template.py
```

This writes `Working/Generated/SkinTemplate.zip`. CMake independently generates its embedded archive at `Working/build/generated/SkinTemplate.zip`, and reconfigures when kit files change. ZIP entries have fixed timestamps and permissions for reproducibility.

All paths under `Working/` are ignored. Older moved CMake caches are archived under `Working/BuildArchive/`; never reuse those caches at their new location. Configure a fresh build directory instead.

## Cross-building the Windows preview on macOS

JUCE 9 rejects MinGW. The preview uses host LLVM/Clang-CL and LLD with Microsoft's CRT/Windows SDK prepared by xwin. Dependencies remain in ignored `Working/Toolchains/`; do not redistribute SDK files as project source. The C++ runtime is linked statically. A native Windows/Visual Studio build remains the recommended release validation path.

With LLVM, LLD, the xwin SDK directory and NSIS installed:

```sh
cmake -S . -B Working/build-windows-msvc \
  -DCMAKE_TOOLCHAIN_FILE=Tools/cmake/windows-clang-cl.cmake \
  -DLLVM_ROOT=/path/to/llvm -DLLD_ROOT=/path/to/lld \
  -DWINDOWS_SDK_ROOT=/path/to/xwin-output \
  -DJUCE_DIR=/path/to/JUCE -DCMAKE_BUILD_TYPE=Release
cmake --build Working/build-windows-msvc --target BigAltedChico_VST3 BigAltedChico_Standalone --parallel 3
python3 Tools/package_windows.py
```

Cross-builds omit the optional VST3 `moduleinfo.json` because JUCE's generator runs a target executable. Hosts can scan the VST3 factory directly. Native builds retain manifest generation. This must be checked with the intended Windows hosts. See [installer testing](INSTALLERS.md).
